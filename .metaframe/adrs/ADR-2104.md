# ADR-2104: Architectural approach for Hacker-Style Encrypted Messaging Interface
**Status:** ACCEPTED | **PRD Reference:** [PRD-2221](../prds/PRD-2221.md) | **Blast Radius Risk:** LOW

## Context
The requirement demands a high-fidelity 'Cyber-noir' aesthetic involving complex visual effects (Matrix rain, scanlines, glassmorphism) and dynamic state-based animations (decryption, pulsing). The architecture must balance these heavy visual effects with a responsive messaging interface.

## Decision
Implement a layered rendering architecture: 1) A dedicated HTML5 Canvas layer for the 'Matrix' background to ensure high-performance animation of thousands of characters. 2) A CSS-driven UI layer for the glassmorphic components, utilizing CSS filters and variables for the 'Cyber-noir' theme. 3) A state-driven animation controller to manage the 'Decryption' and 'Pulse' effects independently of the UI logic.

## Alternatives Considered
1. Pure CSS/SVG for Matrix Rain: Rejected due to the high overhead of managing thousands of DOM elements or SVG paths for the falling character effect.
2. WebGL for background effects: Rejected as it introduces unnecessary complexity and overhead for a 2D canvas-based visual effect.

## Consequences
### Positive
- High visual fidelity and immersive user experience.
- Separation of concerns between the visual effects (Canvas) and the UI components (DOM/CSS).
- Scalable styling via CSS variables for easy theme adjustments.

### Negative & Trade-offs
- Increased client-side resource consumption due to the continuous Canvas animation loop.
- Potential performance overhead on low-end mobile devices.

### Identified Risks
- Potential frame drops if the Canvas loop is not optimized.
- Accessibility concerns regarding the 'flicker' and 'scanline' effects for sensitive users.

## Impacted Modules
- `apps/hacker-chat/index.html`
- `apps/hacker-chat/styles.css`
- `apps/hacker-chat/canvas-engine.js`
